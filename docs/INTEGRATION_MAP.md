# Integration map

This map is the source of truth for which checkout capability is backed by which table, server operation and external boundary. The browser never decides a price, never stores card data, and never marks an order paid.

| UI section / control | Server endpoint | Server operation | Primary tables | External / provider boundary |
| --- | --- | --- | --- | --- |
| Header cart count, product image/name/price, quantity stepper, gift/discount code | `GET /api/bootstrap`, `GET /api/catalog/product`, `PUT /api/cart/quantity`, `POST /api/pricing/quote`, `POST /api/pricing/promotion` | `getFeaturedProduct`, `setCartQuantity`, `createQuote`, `computeDiscount`, `computeTax`, `getRate` | `products`, `skus`, `carts`, `cart_items`, `promotions`, `promotion_redemptions`, `tax_rules`, `shipping_rates`, `shipping_zones`, `quotes`, `quote_lines` | None. All amounts are integer minor units from the server. |
| Sign in, register, guest, forgot password, reset password, logout | `GET /api/identity/session`, `POST /api/identity/{guest,register,login,logout,recovery,reset-password}` | `createGuest`, `register`, `login`, `logout`, `requestRecovery`, `resetPassword`, cart merge | `customers`, `identities`, `sessions`, `recovery_tokens`, `login_attempts`, `carts`, `cart_items`, `outbox_emails` | Email is an outbox row until a delivery adapter is selected. No browser-side hashing. |
| Shipping address, country, method, ETA | `POST /api/shipping/address`, `GET /api/shipping/options` | `validateAddress`, `getShippingOptions`, `getRate` | `shipping_zones`, `shipping_rates`, `compliance_config` | Address validation is local and configurable; no third-party address API is assumed. |
| Review totals, policy links, necessary + optional consent | `GET /api/compliance/config`, `GET /policies/:key`, `POST /api/orders` | `getCompliance`, `getPolicyDocument`, `createOrder` | `compliance_config`, `policy_versions`, `consents`, `orders` | Policy text is draft until reviewed by qualified counsel. |
| Payment method choice and hosted fields | `POST /api/payment/sessions`, `GET /api/payment/hosted-fields/:paymentId`, `GET /api/payment/hosted-checkout?session=...`, `GET /api/payment/session/:sessionId` on return | `createPayment`, `testPaymentProvider.createSession`, `hostedFields`, `getPaymentBySession` | `orders`, `payments`, `test_payment_sessions` | Card data is collected only by a provider-hosted page/iframe. This repository registers a local test adapter only. |
| Pay / decline / cancel on hosted page | `POST /api/payment/test/complete` | `completeHosted`, `applyVerifiedEvent`, `markOrderPaid` / `markOrderFailed` | `test_payment_sessions`, `payments`, `payment_events`, `webhook_events`, `orders`, `inventory_reservations`, `outbox_emails` | Test adapter emits a signed provider event through the same pipeline as a vendor webhook. |
| Provider webhook | `POST /api/payment/webhook` | `verifyWebhook`, `handleWebhook`, `applyVerifiedEvent` | `webhook_events`, `payment_events`, `payments`, `orders` | HMAC signature, timestamp tolerance, event-id dedupe, replay window and monotonic status guards. |
| Confirmation / receipt / pending / failed states | `GET /api/orders/:id`, `GET /api/payment/:id` | `getOrder`, `getPayment`, `mapOrder` receipt assembly | `orders`, `order_items`, `order_addresses`, `consents`, `payments`, `compliance_config` | No success is inferred from a redirect; the browser re-fetches server state. |
| Refund and reconciliation | `POST /api/orders/:id/refund`, `npm run reconcile` | `createRefund`, `reconcilePending` | `refunds`, `payments`, `orders`, `inventory_reservations`, `payment_events`, `outbox_emails`, `audit_log` | Provider interface method `refund`; test adapter returns a deterministic test refund id. |
| Privacy request / export / anonymize | `POST /api/privacy/requests`, `GET /api/privacy/export`, `POST /api/privacy/anonymize` | `createPrivacyRequest`, `exportCustomerData`, `anonymizeCustomer` | `privacy_requests`, `customers`, `carts`, `orders`, `consents`, `sessions`, `recovery_tokens`, `audit_log` | Data subject workflow is wired; retention/enforcement jobs remain operational work. |
| Health, logs, metrics | `GET /api/health`, `GET /api/health/metrics` | request context, redaction, counters | none | pino structured logs; secrets, card data, tokens, passwords and webhook bodies are redacted/never logged. |

## Explicit non-integrations

- No live payment or sandbox vendor is connected. `PAYMENT_PROVIDER=sandbox|live` fails startup until a real adapter is added behind `PaymentProvider`.
- No email, SMS, analytics, fraud, tax or address vendor is called. Those boundaries are either local policy/config or outbox rows.
- No claim of legal compliance or certification is made by the application. Launch gates expose what is still outstanding.
